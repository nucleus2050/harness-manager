# HTTP 需求到代码生成规则

用于用户用自然语言描述业务目标，希望转换为 HTTP 接口调用代码的场景，例如“调用 SM2 签名接口对数据签名”。

进入本子任务后，先同时遵守：

- `references/common-rag-rules.md`
- `references/environment-detection.md`

## 子任务引导

```text
我会先把你的业务需求映射到候选 HTTP 接口，再生成代码。请选择目标输出：

1. 先只确认接口理解，不生成代码
2. 确认后生成 Python 示例
3. 确认后生成 PowerShell/curl 调用
4. 确认后生成 Go/Java 示例
5. 其他，请说明
```

用户可以自由输入，例如“先确认接口，之后我再选语言”。

## 状态机

1. 意图解析：提取业务动作、算法、数据类型、目标接口意图。
2. RAG 检索：查找候选接口路径、方法、参数和注意事项。
3. 复述确认：说明理解到的接口、输入、输出和缺口，请用户确认。
4. 语言确认：若用户未指定输出语言，提供子任务引导菜单。
5. 代码生成：只基于已确认接口事实生成命令或代码。

## 复述确认模板

```text
我理解你的需求是：

- 产品版本：HSM v3.0.1.0
- 业务动作：调用 HTTP 接口完成 SM2 签名
- 候选接口：接口名称、请求方式、路径
- 输入数据：待签名原文、算法、密钥或证书标识
- 预期输出：签名结果或错误信息
- 仍需确认：目标服务地址、端口、协议、真实密钥索引

请确认这个理解是否正确；确认后我再生成代码。
```

用户确认前不要生成最终代码。

## 生成规则

- 用户只说“调用 SM2 签名”时，不能直接生成代码。
- 如果 RAG 检索到多个候选接口，列出候选项和来源，让用户选择。
- 如果关键参数缺失，先询问缺失项。
- 确认后可复用 `test-command.md` 或 `single-interface-example.md` 的输出规则。
- 生成结果必须包含接口事实、参数说明和 RAG 来源。

## 输出结构

信息充足时（用户已确认）：

- 已确认运行环境和工具链状态。
- 接口事实表。
- 可直接运行的命令或代码。
- 运行方式。
- 参数说明。
- RAG 来源引用。

信息不足时（无法确认接口）：

- 当前不能生成的原因。
- RAG 结果覆盖的已知信息和仍缺口的字段。
- 下一步只问必要信息，不要求用户一次性补全所有参数。
