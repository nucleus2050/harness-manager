# SMClaw RAG 使用规范

## 核心原则

回答密码产品相关问题前，必须先确认具体产品和版本，再使用 `smclaw-rag` MCP 查询本地 RAG。不要默认使用某个产品或版本，不要跨产品、跨版本混用结果。

`product` 和 `version` 是独立参数；`query` 只写用户真正要查的接口、配置项、错误码、现象或操作。严禁在 `query` 中重复带入产品名和版本号，因为产品和版本已经由参数限定，写入 `query` 会让向量检索偏离实际语义。

## 触发范围

当用户询问以下内容时使用本技能：

- 密码产品接口、HTTP API、SDK API、示例代码、参数含义。
- 产品安装、初始化、证书、license、服务启动、配置项。
- 售后、排障、错误码、日志、连接失败、白名单、SSL、网络等问题。
- 任何需要从 SMClaw 产品文档、接口文档、售后文档中获取依据的问题。

不要用于纯通用编程问题，除非问题需要结合密码产品文档。

## MCP 服务

使用 MCP 服务：`smclaw-rag`。

## MCP 接口

| 工具 | 参数 | 用途 | 何时使用 |
|:---|:---|:---|:---|
| `smclaw_list_products` | 无 | 列出本地可用产品类型。 | 用户未明确产品，或需要核对当前包支持哪些产品。 |
| `smclaw_list_versions` | `product` | 列出某个产品可用的文档/知识库版本。 | 用户未明确版本，或需要核对某产品有哪些版本。 |
| `smclaw_rag_search` | `product`, `version`, `query`, 可选 `top_k` | 在指定产品和版本的本地 RAG 中检索文档片段。 | 产品和版本已确认后，回答产品文档事实前必须调用。 |

`smclaw_rag_search` 的结果中重点使用：

- `content`：可用于回答的片段正文。
- `source_name`、`source_path`、`chunk_index`：必须优先引用的来源字段。
- `heading`、`page_number`、`sheet_name`、`slide_number`：存在时一并引用。

## 必须先确认产品和版本

查询 RAG 前检查用户输入：

| 信息 | 规则 |
|:---|:---|
| 产品 | 必须明确，例如 `HSM`、`CSP`、`CHSM`。 |
| 版本 | 必须明确，例如 `v3.0.1.0`。 |
| 查询问题 | 保留接口名、错误码、配置项、日志关键字、产品术语；不要包含产品名和版本号。 |

如果产品或版本缺失，先只问一个澄清问题，不要查询：

```text
请先确认要查询的产品和版本，例如 HSM v3.0.1.0。您这次要查哪个产品版本？
```

如果用户只说“密码机”“签名验签”“接口报错”等模糊表达，也必须确认产品和版本。

## 查询流程

1. 产品不明确：调用 `smclaw_list_products` 获取可用产品，再请用户确认。
2. 版本不明确：调用 `smclaw_list_versions` 获取该产品可用版本，再请用户确认。
3. 产品和版本都明确后：调用 `smclaw_rag_search`。
4. 首轮结果不足、问题包含多个接口/错误码，或用户要求更全面时，才提高 `top_k`。

## 查询示例

用户问题：

```text
HSM v3.0.1.0 签名验签 HTTP 服务接口怎么调用？
```

正确 MCP 调用：

```json
{
  "tool": "smclaw_rag_search",
  "arguments": {
    "product": "HSM",
    "version": "v3.0.1.0",
    "query": "签名验签 HTTP 服务接口怎么调用",
    "top_k": 10
  }
}
```

错误 MCP 调用：

```json
{
  "tool": "smclaw_rag_search",
  "arguments": {
    "product": "HSM",
    "version": "v3.0.1.0",
    "query": "HSM v3.0.1.0 签名验签 HTTP 服务接口怎么调用",
    "top_k": 10
  }
}
```

错误原因：`query` 重复包含 `HSM` 和 `v3.0.1.0`，会把向量检索重点拉向产品/版本字符串，而不是“签名验签 HTTP 服务接口”。

## 回答规则

- 基于 RAG 返回的 `content` 回答；证据不足时明确说明“当前知识库未检索到足够依据”。
- 回答中引用来源字段，优先包含 `source_name`、`source_path`、`chunk_index`，有 `heading`、`page_number`、`sheet_name`、`slide_number` 时一并引用。
- 如果用户要求生成接口命令或代码，先说明依据来自哪个产品版本的文档，再给示例。
- 如果用户想比较多个产品或版本，分别确认范围，分别查询，并在回答中标明每条结论对应的产品版本。
- 不要凭记忆补接口路径、参数名、错误码含义或配置默认值。

## 常见错误

| 错误 | 正确做法 |
|:---|:---|
| 用户没说版本就查询默认版本 | 先询问产品和版本。 |
| HSM 查询结果用于 CSP/CHSM | 按用户确认的产品版本单独查询。 |
| `query` 写成 `HSM v3.0.1.0 签名接口` | `product=HSM`、`version=v3.0.1.0`、`query=签名接口`。 |
| 只给结论不列来源 | 附上 RAG 来源字段。 |
| RAG 结果弱仍编造答案 | 明确证据不足，并建议用户补充产品版本、接口名、错误码或文档。 |
