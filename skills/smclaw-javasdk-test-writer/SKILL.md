# SMClaw Java SDK 测试编写助手

## 目标

在已经通过 `/javasdk_init` 初始化的 Java SDK 测试工程中添加接口测试，不重建工程结构。优先复用初始化生成的 Maven/Gradle 配置、测试基类、设备会话 fixture 和 `HsmSessionTestCase` 风格的会话管理。

## 依据要求

- Java SDK 类名、方法签名、参数对象、异常类型、返回字段和调用顺序必须来自官方 Java SDK 文档或 `smclaw-rag` 检索证据。
- RAG 或官方依据不足时不要伪造 API、包名、异常类或断言字段。
- 不要伪造密钥口令、管理员凭据、用户 PIN、token、证书私钥或生产设备参数。
- 真实设备测试需要用户明确授权，并使用初始化工程的受控配置注入敏感值。

## 工作流程

1. 阅读 `/javasdk_init` 工程的 README、构建文件、测试目录、配置样例和 `HsmSessionTestCase` 用法。
2. 查询 RAG，确认目标 Java SDK 接口的类、方法、异常、前置登录/会话要求和示例。
3. 在现有测试包中新增或扩展最小测试类，遵守工程命名、断言库和生命周期管理。
4. 默认运行可用的编译验证，例如 Maven/Gradle test compile；可离线执行的测试也一并运行。
5. 需要连接 HSM/CSP/CHSM 真实设备时，先说明风险并获得授权。

## 测试设计

- 成功路径校验返回对象、状态码、输出长度、算法结果或文档定义的关键字段。
- 失败路径覆盖非法参数、缺失配置、未登录会话、权限不足和设备返回错误等有依据场景。
- 测试代码不得把真实口令、密钥或证书写入源码；使用初始化工程的配置读取机制。
- 对会改写设备状态的用例加保护条件、清理逻辑和授权提示。

## 输出要求

- 列出新增 Java 测试类、资源文件和配置样例路径。
- 给出默认编译或测试命令；缺少 JDK、构建工具或 SDK jar 时说明验证限制。
- 标注官方/RAG来源，尤其是方法签名、参数约束、异常和返回字段依据。
- 明确区分离线编译验证和需要真实设备授权的集成测试。
